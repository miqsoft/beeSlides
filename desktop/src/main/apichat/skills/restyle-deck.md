---
name: restyle-deck
description: Give an existing deck a new look (a glow-up, a new style, a template to follow) while keeping every slide's content — one deck stylesheet (and the deck's slide types restyled, if it has them), every slide rewritten in it, then a polish pass.
---

Give the deck a new look. Keep its content exactly: every word, number, picture and the slide order stay; element ids stay (morph pairs, comments and links hang on them). Only how it looks changes. To merely fix alignment and spacing use polish-deck instead; for one slide, slide-designs.

1. **Read the deck.** `doc_info` (theme, slideTypes, designRules), `outline` (each slide's current `slideType`) and the design rules once: `read_reference("design.md")`. `review_slide` 3–4 representative slides (the cover, a typical content slide, the busiest one).
2. **One question.** Infer the profile from the deck (purpose, typical slide, simplicity, decoration, motion — see build-deck step 2) and ask once (with your question tool if you have one, else in one message): the inferred profile for correction, and what should change ("calmer", "more visual", "more modern", "follow this template"). If the request already says enough, or the user wants no questions, state your reading in one line and go on.
3. **Classify every slide.** A table in chat, one row per slide: id, its message (from its title or main text — unchanged), its evidence kind (the list in build-deck step 3), and the slide type it will follow. This is the deck's outline; content that would read better as another kind (five numbers in a text list → a chart or a table) is a suggestion in the table, not a change, unless the user asked for more visual slides.
4. **Pick the look with the user.** Offer 2–3 looks for the most typical content slide with ONE `propose_variants` call: start from the starter looks in design.md that fit the profile, keep the slide's own content and ids in each, and give each its `theme` (its diagrams then show in its colours, and picking it sets the deck theme). Then do what the result says (outside the app: `variants` `{op:"previews"}` for the BeeSlides pane), and with a question tool also ask "Which look?", one option per design. Learn the pick from `variants` `{op:"status"}`; an answer status does not show yet, apply with `variants` `{op:"pick"}`. Settle the pick before step 6: an open set covers your `review_slide` screenshots in the app. Without questions, build one look closest to the profile and say so.
5. **The deck stylesheet** in the chosen look (build-deck step 5: the type scale as classes, the motif, the colour meanings, the theme).
   - **The deck already has slide types:** restyle them in place — `slide_html` read and write on each type, keeping its placeholder ids — so every linked slide follows at once. If one type carries slides of different evidence kinds (a single "content" type for everything), make it the parent and add a child per kind, then relink each slide to its kind's child — that is what lets a comparison and a one-result slide each get the arrangement they need.
   - **The deck has none:** every slide is reworked in step 6 with the deck stylesheet. Only when the user asks for a template, create the family (build-deck step 5) and `slide_type` `{op:"relink", layoutId, slideId}` per slide; `verdict` `partial` lists `floating` content that found no placeholder — note those slides for step 6.
   - The theme change recolours every element that refers to the palette; hex colours an earlier writer typed by hand do not follow — find them in step 6.
6. **Rework the slides that need it.** Without slide types every slide; with them the floating ones, slides whose arrangement no longer fits their type, and slides with hand-typed colours or fonts outside the new look: `slide_html` read, change the arrangement and styling to the deck stylesheet's classes (never the text), and write back with the same ids — several slides in one `slide_html` `{op:"write", css, slides:[…]}` call. More than 6 such slides: hand them to writers in consecutive runs with build-deck's writer block, adding "keep every word, number and element id; change only the arrangement and styling".
7. **Check.** Run the polish-deck pass over the whole deck (its consistency step compares slides of one type), start build-deck's critic for 8 or more slides and fix what it names, then `validate` once.
8. **Report** in two or three lines: the new look in one line, slides relinked or reworked, anything left (content that did not fit and why, suggestions from step 3).
